# Settings

luamemo reads its settings from `MEMO_<NAME>=value` lines — in a settings file or
in the environment. Every setting it knows is listed below; `memo config list`
shows the value of each one in force and where it comes from.

## Where settings live

| Where | Holds | Written by |
|---|---|---|
| `<project>/.luamemorc` | this project's settings: its database, its embedder | `memo calibrate`, `memo config set` |
| `~/.luamemorc` | defaults for every project on this machine | `memo config set --user` |
| the environment | `MEMO_*` variables of your shell (an MCP client started through `memo mcp` passes none) | you |

A later source wins: the environment < `~/.luamemorc` < the project's
`.luamemorc`. **The project** is the one named by `memo calibrate --root DIR` /
`memo mcp --project DIR`, else `MEMO_PROJECT` when set, else the nearest
directory from where you are, upward, that holds a `.luamemorc` — so `memo` works
the same from any subfolder of a project (the home directory's own `~/.luamemorc`
is the user file, never a project) — else the current directory. `memo mcp`, the
MCP server an MCP client starts, finds the project the same way from the client's
working directory, so the client's config needs no `MEMO_*` variables. (Started
directly as `luajit mcp/server.lua`, the server reads the same files, but there a
variable the client's config passes wins.) `~/.memorc`, the older name of the user file, is no longer
read: `memo calibrate` moves its settings into `~/.luamemorc` (a setting already
there is kept) and removes it.

- **Settings files are data.** Each line is `MEMO_NAME=value` (an `export` in
  front is allowed). `'Single quotes'` keep a value literally; `"double quotes"`
  and bare values expand `$NAME`, `${NAME}` and a leading `~/`; a bare value ends
  at ` #`. Nothing in the file is ever run.
- **A project's `.luamemorc` is used when memo wrote it or you trusted it.** One
  committed to git came with the repository, and one in a downloaded folder (a zip,
  a tarball, a copy) came with it — not from you — and could point the database or
  the embedder somewhere else, with your vault's keys in its headers. luamemo
  ignores such a file (and says so) until you review it and run `memo config trust`
  — once per machine, and again whenever the file changes (a `git pull`, an edit by
  hand). memo's own writes (`memo calibrate`, `memo config set`) keep it trusted. The
  `.luamemorc` that `memo calibrate` writes is kept out of git.
- **A project's file never names code to run.** `MEMO_LUA`, `MEMO_LIB_SQLITE3`,
  `MEMO_LIB_SODIUM` and `MEMO_GGUF_SHIM` come only from the environment and
  `~/.luamemorc`; in a project's file they are ignored (and memo says so).
- **No credential goes into a settings file.** A header that needs an API key
  refers to the vault instead: store the key with `memo secret-store NAME` (it
  asks for the value without echoing it), then
  `memo config set MEMO_EMBEDDER_HEADERS '{"Authorization": "Bearer {secret:NAME}"}'`.
  The key is read from the vault when a request is made and masked in errors;
  `memo config set` refuses a plain-text credential.
- **People change settings; agents only read them.** `memory_status` with
  `details: true` lists every setting, its value and its source; no MCP tool
  changes one — a new embedder, for instance, makes every stored vector
  incomparable until `memo reembed --all`. A running MCP server picks up a change
  when it restarts.

## `memo config`

```bash
memo config list [--json]            # every setting: value and where it comes from
memo config get KEY                  # the value in force
memo config set KEY VALUE [--user]   # checked (type, range, allowed words), then written
memo config unset KEY [--user]
memo config check                    # values that don't parse, MEMO_ names luamemo doesn't read
memo config trust                    # use this project's .luamemorc as it is now (one memo didn't write)
memo config list --markdown          # the reference tables below
```

`KEY` is `MEMO_DEDUP_THRESHOLD`, `DEDUP_THRESHOLD` or `dedup_threshold`. `set`
writes the project's `.luamemorc` (with `--user`: `~/.luamemorc`) and says when a
change needs `memo reembed --all` or a new `memo calibrate` run. luamemo warns
once about a `MEMO_` name it doesn't read — naming the closest setting — and
about names older versions read (`MEMO_DB_URL`, `MEMO_SECRETS_FILE`, …), saying
what replaced them. A value that doesn't parse is ignored with a warning, except
for the few settings marked below where a mistake must stop luamemo instead.

## Reference

*Accepts*: what the setting takes. *Default*: what applies while it is unset
(— : nothing is set; the feature is off, or the module decides).

### Project

| Setting | Accepts | Default | Meaning |
|---|---|---|---|
| `MEMO_DB` | text | — | The project's database: a name (a file in ~/.local/share/luamemo) or a path. memo calibrate gives each project its own. Set only in your shell, `memo calibrate` offers to save it in `.luamemorc` (an MCP client starts the server without your shell's settings). |
| `MEMO_SCOPE` | text | — | This project's scope: MCP tools, memo write, memo brief and memo sense use it when a call names none. Set only in your shell, `memo calibrate` offers to save it in `.luamemorc` (an MCP client starts the server without your shell's settings). |
| `MEMO_MCP_TOOLS` | `all` · `core` | `all` | The tools the MCP server offers: all, or core — brief, search, write, recent, get, update, delete, promote, sense, status, the code map and secret_list / secret_execute: fewer tool descriptions in every session's context. The others stay on memo. |

### Embedder

|---|---|---|---|
| `MEMO_EMBEDDER` | `hash` · `gguf_ffi` · `hash_learned` · `projected` | `hash` | In-process embedder, used when MEMO_EMBEDDER_URL is unset: hash (pure Lua, word-level), gguf_ffi (a GGUF model run through llama.cpp — MEMO_GGUF_MODEL), hash_learned / projected (hash or another base with a projection learned from use; the base unchanged until one is trained). Changing it: `memo reembed --all`. An invalid value stops luamemo (it is never ignored). | `MEMO_EMBEDDER_URL` | text | — | HTTP embedder endpoint; when set, it is used instead of the in-process one. Changing it: `memo reembed --all`. Set only in your shell, `memo calibrate` offers to save it in `.luamemorc` (an MCP client starts the server without your shell's settings). |
| `MEMO_EMBEDDER_ADAPTER` | `generic` · `ollama` · `openai` · `openai_compatible` · `tei` · `voyage` · `cohere` · `deepseek` · `anthropic` | `generic` | Request format of the HTTP embedder. ### Writes

| Setting | Accepts | Default | Meaning |
|---|---|---|---|
| `MEMO_DEFAULT_SCOPE` | text | `global` | Scope of a memory written without one (and without MEMO_SCOPE). |
| `MEMO_DEFAULT_IMPORTANCE` | number, 0–10 | `1` | Importance of a memory written without one (0–10, a ranking weight). |
| `MEMO_DEFAULT_DECAY_RATE` | number, 0–1 | `0` | Daily decay of a memory written without one (0: none). |
| `MEMO_DEDUP_ENABLED` | true / false | `true` | Check each write for a near-identical memory in its scope. |
| `MEMO_DEDUP_THRESHOLD` | number, 0–1 | `0.95` | Similarity at which a write counts as a duplicate. |
| `MEMO_DEDUP_STRATEGY` | `update` · `skip` · `append` | `update` | On a duplicate: update (merge into it), skip, or append (keep both). |
| `MEMO_DEDUP_CANDIDATE_LIMIT` | whole number ≥ 1 | `1000` | Rows a batch write compares against, per scope. |
| `MEMO_PATTERNS_ENABLED` | true / false | `true` | Extract first-person preferences ("I prefer …") from writes into companion memories. |
| `MEMO_PATTERNS_MAX_BODY_CHARS` | whole number ≥ 0 | `5000` | Longer bodies are not scanned for preferences. |
