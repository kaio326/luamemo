# Recall benchmark — hash vs. nomic-embed-text

> Historical record, kept as measured on an earlier luamemo (the corpus generator it names
> is gone). The current benchmark numbers are in [eval/README.md](../README.md#results).

Result of running [`eval/recall_bench.lua`](../recall_bench.lua) on the 33-question
synthetic LongMemEval-style corpus generated by
[`eval/_make_synthetic.lua`](../_make_synthetic.lua) (11 topical clusters,
paraphrased questions, topical near-miss decoys + cross-cluster off-topic
decoys). Each question wipes the scope, writes its haystack of session
snippets as memories (`metadata.session_id`), then issues `memory.search`
and checks whether any of the gold session IDs appears in the top-k.

| metric        | hash (in-process, dim=384) | ollama nomic-embed-text (dim=768) |
|---------------|---------------------------:|----------------------------------:|
| recall@1      |                      63.6% |                             84.8% |
| recall@5      |                      87.9% |                             93.9% |
| recall@10     |                      97.0% |                            100.0% |
| recall@20     |                     100.0% |                            100.0% |
| MRR           |                      0.748 |                             0.896 |
| median rank   |                          1 |                                 1 |
| tail misses   |                   0 / 33   |                          0 / 33   |
| elapsed       |                       2 s  |                          470 s    |

Backend in both runs: `bruteforce` (cosine over Postgres `real[]`).

## What this means

- **Real semantic embeddings clearly help on paraphrased queries.** The
  corpus deliberately strips keyword overlap between Q and the gold
  session, so the hash embedder (which is essentially a token-level
  feature hash) bottoms out at ~64% R@1. Swapping to `nomic-embed-text`
  closes most of that gap (+21.2 pp R@1, +14.8 pp MRR) without changing
  a single line of library code — only `setup()` config.
- **Both embedders saturate by k=20**, so the brute-force backend +
  default search weights are not the bottleneck on this corpus.
- **Speed cost is real.** The hash embedder runs in-process at ~16 ms
  per question end-to-end; Ollama on CPU averaged ~14 s per question
  (~1 s per embed × ~14 sessions per question + 1 query). For CI the
  hash embedder remains the correct default; real embedders are an
  opt-in for production deployments.

## Reproducing

```bash
# Hash baseline (offline, fast):
PGHOST=127.0.0.1 PGDATABASE=lm_bruteforce_test \
    lua5.1 eval/recall_bench.lua --embedder hash --out eval/results/recall_hash.json

# Ollama (requires `ollama serve` + `ollama pull nomic-embed-text`):
PGHOST=127.0.0.1 PGDATABASE=lm_bruteforce_test \
    lua5.1 eval/recall_bench.lua --embedder ollama --out eval/results/recall_ollama.json
```

The Ollama path uses [`eval/_resty_http_shim.lua`](../_resty_http_shim.lua),
a LuaSocket-backed shim for `resty.http` that lets the harness run under
plain `lua5.1` (no OpenResty needed). The shim is preloaded only by the
benchmark script — the library itself is unchanged.

## CI mode

For pipelines that want a deterministic regression guard without any
network or model dependency, the harness has a `--mode ci` flag:

```bash
PGHOST=127.0.0.1 PGDATABASE=lm_bruteforce_test \
    lua5.1 eval/recall_bench.lua --mode ci
```

CI mode forces the hash embedder + the canonical 33-question corpus,
runs in ~2 s, and asserts that every metric in the table above matches
the locked baseline within `--tol` (default `0.001`). Non-zero exit on
drift. Update the `CI_BASELINE` block in `eval/recall_bench.lua` if and
only if the corpus or the hash embedder is changed intentionally.

## Phase 16.4 — failure-mode diagnostics + adversarial paraphrase (2026-05-04)

The bench gained two new flags:

| Flag                         | Purpose                                                          |
|------------------------------|------------------------------------------------------------------|
| `--diagnostics`              | Search at `--k-diag` (default 100) and bucket each question into `hit` / `ranked_below_k` / `missing_from_candidates` |
| `--k-diag N`                 | Wider candidate pool used only when `--diagnostics` is set       |
| `--paraphrase det`           | Generate `--paraphrase-n` deterministic adversarial variants per question (no LLM); aggregate paraphrase R@K + MRR + robustness ratio |
| `--paraphrase-n N`           | Variants per question (default 3)                                |
| `--paraphrase ollama`        | Reserved hook for LLM paraphrasing — not yet wired               |

The deterministic paraphraser (`eval/paraphrase.lua`) chains three
transforms — synonym swap, prepositional-phrase reorder, function-word
drop — and falls back to a discourse marker (`"Specifically, "` /
`"Regarding the topic, "` / `"Note: "`) when no rule fires. All
transforms are pure-Lua and deterministic; rerunning produces identical
variants. 6 unit tests at `eval/smoke_paraphrase.lua`.

### Measured results (n=33 synthetic corpus)

| Embedder              | Base R@1 | Base R@5 | Para R@1 | Para R@5 | Robust@5 | Dominant failure |
|-----------------------|---------:|---------:|---------:|---------:|---------:|------------------|
| `hash` (n=20)         | 70.0%    | 90.0%    | 58.3%    | 81.7%    | 0.907    | none (all hit)   |
| `nomic-embed-text`    | 84.8%    | 93.9%    | 78.8%    | 96.0%    | **1.022**| none (all hit)   |

**Reading**

1. The synthetic corpus is **saturated** for `nomic-embed-text` at
   n=33 — every gold session is in the top-20 candidate pool, so the
   `by_failure_mode` buckets cannot discriminate. To exercise the
   diagnostics, switch to a harder corpus (LongMemEval `_s` n≥200) or
   inflate the haystack size.
2. The hash embedder shows the expected adversarial degradation
   (-8.3 pp R@5 under paraphrase). This is the floor.
3. `nomic-embed-text` is **paraphrase-robust** on this corpus
   (robustness@5 > 1.0). This is consistent with its training on
   paraphrastic NLI data — synonym swaps and word-order flips do not
   move the embedding far enough to drop the gold session out of the
   top-5. R@1 still drops 6 pp under paraphrase, suggesting the model's
   *exact-match* head is more brittle than its *semantic-vicinity* head.
4. Without `--diagnostics`, the `by_failure_mode` block still prints —
   `ranked_below_k` and `missing_from_candidates` are folded together
   because the search never looks past `--k-max`.

### Reproducing

```bash
# diagnostics + paraphrase, on the synthetic corpus (cached on disk):
PGHOST=127.0.0.1 PGDATABASE=lm_bruteforce_test \
  OLLAMA_MODEL=nomic-embed-text OLLAMA_DIM=768 \
  lua5.1 eval/recall_bench.lua --embedder ollama --n 33 \
    --diagnostics --paraphrase det --paraphrase-n 3 \
    --out eval/results/recall_ollama_phase164.json
```

### Limitation (logged for follow-up)

The synthetic corpus is too easy to surface meaningful
`by_failure_mode` distributions on a competent embedder. Re-running
this protocol against the LongMemEval `_s` corpus (where `nomic` only
hits R@5=0.82) would saturate fewer questions and produce a useful
dominant-failure-mode signal. A separate driver
(`eval/recall_bench_lme.lua`) that reads the LongMemEval shape instead
of the synthetic shape is the natural next step; tracked under the
"recall_bench v3" follow-up.
